# Threat Model — Zenith

Assets: user accounts, saved papers/prefs, Mem0 memories, paper corpus + embeddings, LLM spend, legacy crawled full text, run results, private project notes/sources, and extracted PDF page text (raw PDF bytes are not retained).
Actors: anonymous internet, authenticated user (malicious or compromised), malicious paper/author, compromised upstream APIs (arXiv/HF/S2/Crossref/GitHub), provider outage. Firecrawl is not contacted by the current runtime.
Trust boundaries: browser→FastAPI (JWT/SSE token) → Supabase (service-role client for server-owned operations) → Redis → configured LLM providers; public metadata is fetched only from fixed provider endpoints. Private project PDF text stays in Postgres and is not sent to an LLM by current routes → (future) GitHub/MCP/sandbox.
STRIDE/abuse cases: spoofed JWT (alg confusion, cross-project token) → §5.2 allowlist + iss/aud; IDOR on run_id/paper saves/project PDFs → ownership checks + RLS; user-controlled URL fetching is disabled, including the hosted Firecrawl helper and its legacy cache reader; fixed-provider HTTP clients require host-bound URLs and bounded requests; prompt injection via paper text, private PDF text, or saved title → treat as untrusted source data, filter instruction-like spans, and do not forward private PDFs to providers; wallet drain via anonymous search / reconnect loops → auth + quotas + start-once; info disclosure via `str(e)` errors/Langfuse traces/account export → generic errors, scoped export, and redaction. Legacy `crawled_content` rows remain stored but are not read or written by the application; explicit cleanup and retention policy remain open.
Residual risk: service-role client use and project PDF RLS/export/deletion cascades require live staging verification; deployed proxy Authorization-header redaction, provider behavior, and observability redaction remain unverified.
