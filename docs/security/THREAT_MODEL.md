# Threat Model — Zenith

Assets: user accounts, saved papers/prefs, Mem0 memories, paper corpus + embeddings, LLM spend, crawled full text, run results, private project notes/sources, and extracted PDF page text (raw PDF bytes are not retained).
Actors: anonymous internet, authenticated user (malicious or compromised), malicious paper/author, compromised upstream API (arXiv/HF/PWC/S2/Firecrawl), provider outage.
Trust boundaries: browser→FastAPI (JWT/SSE token) → Supabase (service-role today ⚠) → Redis → configured LLM providers → public external pages/PDFs; private project PDF text stays in Postgres and is not sent to an LLM by current routes → (future) GitHub/MCP/sandbox.
STRIDE/abuse cases: spoofed JWT (alg confusion, cross-project token) → §5.2 allowlist + iss/aud; IDOR on run_id/paper saves/project PDFs → ownership checks + RLS; SSRF via paper URL/PWC `repositories` → SSRF validator; prompt injection via paper text, private PDF text, or saved title → treat as untrusted source data, filter instruction-like spans, and do not forward private PDFs to providers; wallet drain via anonymous search / reconnect loops → auth + quotas + start-once; info disclosure via `str(e)` errors/Langfuse traces/account export → generic errors, scoped export, and redaction; cache poisoning via `crawled_content` keyed by paper_id only → key by (paper_id,url,parser_version).
Residual risk: service-role still used until user-scoped client lands; project PDF RLS and export/deletion cascades need live staging verification; PWC liveness and Langfuse redaction remain unverified.
