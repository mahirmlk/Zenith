## Why this matters

`npm audit` reports 6 vulnerabilities (1 critical, 5 moderate) in `esbuild`, `postcss`, `vite`, and `vitest`. These are all dev/build dependencies, but the critical vulnerability in `esbuild` is a build-time supply-chain risk. Additionally, `@testing-library/dom` is listed in production `dependencies` instead of `devDependencies`, bloating the production bundle.

## Steps

### Step 1: Move `@testing-library/dom` to devDependencies

In `frontend/package.json`, move the line:
```json
"@testing-library/dom": "^10.4.1",
```
from the `dependencies` block to the `devDependencies` block.

**Verify**: `grep -A20 "devDependencies" frontend/package.json` — should contain `@testing-library/dom`

### Step 2: Run `npm audit fix`

```bash
cd frontend && npm audit fix
```

This applies non-breaking patches. If it says "fix available via `npm audit fix --force`" for some packages, note which ones — those require major version bumps.

**Verify**: `cd frontend && npm audit` — check remaining vulnerabilities

### Step 3: If vulnerabilities remain, bump specific packages

If `postcss` is still vulnerable, bump it:
```bash
cd frontend && npm install postcss@latest
```

If `vitest` or `vite` are still vulnerable:
```bash
cd frontend && npm install vitest@latest vite@latest
```

**Important**: After each bump, run `npm run build` and `npm test` to verify nothing breaks.

**Verify**: `cd frontend && npm audit` — 0 vulnerabilities (or only informational)

### Step 4: Verify build and tests

```bash
cd frontend && npm run build
cd frontend && npm test
```

**Verify**: both exit 0
